# Plan 33 — Direction spike: opt-in revocable share links

Decide whether Exhibit gets opt-in, revocable, read-only share links for single artifacts, and write that decision as a memo appended to this plan. The memo validates or overturns the strawman design below against the code, lists every security-invariant change for Henry to accept or reject, and ends with a verdict. This plan changes no source, test, schema, or CLAUDE.md line. Build phases come later, through `blueprint update 33`, and only if Henry accepts the memo.

- **Risk**: HIGH for the feature (first unauthenticated route that serves owner content). The spike is LOW: it writes only this file.

## Why this matters

Every publish tool tells Claude that the returned URL "is not a link to share" (`src/lib/mcp/server.ts:156`, `:206`, `:256`; `src/lib/mcp/url.ts:3`). So a publish to Exhibit ends at "take a screenshot" whenever the owner wants someone else to see the result. A share link fixes that, but it changes the project's core stance: one owner, and no artifact content without a session. "Not worth doing" is a valid verdict. The spike exists so Henry decides on evidence, before anyone writes code.

## Phase 1 — Decision memo

**Goal**: this file gains a `## Decision memo` section that holds a one-line verdict, a threat model, the invariant changes for Henry to accept, the feasibility evidence, and a phased build proposal. Nothing else in the repo changes.

**Decisions** — the strawman. The memo confirms each item with `file:line` evidence, or overturns it with evidence and a replacement:

- Table `share_links` in `src/database/schemas/share-link.ts`: `id` text PK, `token` text unique not null, `artifactId` text FK to `artifacts.id` with `onDelete: cascade`, `version` integer not null, `createdAt` integer not null, `revokedAt` integer nullable. At most one unrevoked link per artifact, enforced by a partial unique index on `artifact_id where revoked_at is null`.
- `version` is pinned, not nullable. A follow-latest link would silently publish every later `update_artifact` (including edits by Claude) to everyone who holds the link. The owner shares a new version by revoking and minting again.
- Token: 32 bytes from `crypto.getRandomValues`, base64url (43 chars), stored in plaintext. Hashing buys nothing here: the same database holds every artifact body, so a database leak exposes the content anyway. Plaintext also lets the owner copy the link again.
- URLs: `/s/:token` is the chrome-free viewer page for spec and markdown. `/s/:token/raw` serves html bytes with `RENDER_CSP`, and `/s/:token` redirects there for html artifacts. The memo names the exact route files. It must also confirm, against TanStack flat-route rules and `src/routeTree.gen.ts`, that the raw route does not nest under the page route's component or loader.
- Public read path: one server fn without `sessionMiddleware`, in a new `src/lib/share-links.ts`. It returns only `{ title, type, body }`. It never returns saved state, versions, answers, tags, or description. Unknown, revoked, and soft-deleted tokens all return the same 404, so a response never tells a revoked token apart from one that never existed.
- Interaction state: the share view never reads `artifact_states`. It renders with a fresh in-memory store that has no subscriber, so no save fn is reachable. A viewer can toggle controls locally, and the result is lost on reload.
- Response headers on both share routes: `Referrer-Policy: no-referrer` (the token is in the path), `X-Robots-Tag: noindex, nofollow`, `Cache-Control: no-store` (revocation takes effect at once, through any proxy). The memo names the TanStack Start mechanism that sets headers on an SSR page response.
- Revocation: the owner revokes a link explicitly. `softDeleteArtifact` also revokes every link, so a restore from trash never brings a link back. Purge relies on the cascade. Archive does not revoke: it hides an artifact from the gallery list, it does not unpublish it.
- Owner UI: a "Share link" item in the detail view's `DropdownMenu` (`src/components/artifacts/artifact-detail.tsx:303-350`) opens a dialog to create, copy, and revoke the link. It uses session-guarded server fns.
- MCP: no tool mints, lists, or revokes links. An MCP client acts on text it did not write, so a minting tool gives prompt injection a way to make private artifacts public. The tool descriptions at `server.ts:156`, `:206`, `:256` stay true, because the returned URL is still owner-only.
- No new rate limiter. A 256-bit token makes guessing infeasible, and the Better Auth limiter does not reach app routes. The memo either agrees or names a concrete attack that a limiter stops.
- Map on share pages: accept the Carto fallback. Don't add a public key endpoint.

## Decision memo

Verdict: BUILD
Build share links for spec and markdown artifacts only; HTML artifacts keep `/download` as their share path. Two findings would change this verdict to DO NOT BUILD: Henry rejects invariant row 1 (a public route that serves owner content), or Henry decides that the sandboxed `/download` file is an adequate share path for spec artifacts too. It is not adequate today, because a spec downloads as JSON and the recipient has no renderer (`src/routes/download.$id.$n.ts:24`).

### Summary

- The strawman holds for the data model, token, revocation, state isolation, headers, MCP stance, rate limiting, and the map. Each item has evidence below.
- One item is overturned: the `/s/:token/raw` HTML route. `/download/:id/:n` already exports an HTML artifact as a sandboxed attachment (`src/routes/download.$id.$n.ts:25`, `:35`, `:57-67`). The owner can send that file, and it runs on the recipient's machine, not on the owner's domain. A public raw route would add the only share surface that runs author script on the owner's domain, and it would amend the `CLAUDE.md` HTML-surface line. The value gap is spec, the preferred format, which has no portable export. Row 2 below keeps HTML sharing as an explicit owner decision. The route-nesting evidence for the raw route is recorded for the case where Henry accepts that row.
- New finding: the Weather block (in progress, untracked `src/lib/weather.ts`) calls `getForecastFn`, which is session-guarded like the map key fn. On a share page, the map falls back to Carto, and the Weather block shows its error state. Both degrade; neither breaks.
- Drift since `ffee99b`: the MCP "not a link to share" descriptions moved to `src/lib/mcp/server.ts:224`, `:246`, `:269`. `CLAUDE.md` invariant lines shift while other plans edit that file (the public-route line is `:40` and the HTML-surface line is `:41` at the time of writing), so this memo names them by content: the public-route line and the HTML-surface line. Repository functions moved about 20 lines down (`getArtifact` `:368`, `softDeleteArtifact` `:642`, `restoreArtifact` `:651`, `purgeArtifact` `:666`), and other executors edit that file now, so the build phases must locate them by symbol. Plan 07 has landed: `src/lib/server-fn-protection.unit.test.ts:13-16` is the server-fn allowlist. No drift changes a decision.

### Build proposal

Each phase closes with `mise exec -- pnpm gate` and `git status` limited to the phase's files.

1. Schema and repository. Goal: the `share_links` table, the partial unique index, and the repository functions `createShareLink`, `getShareLink`, `revokeShareLink`, `getSharedArtifact`, with `softDeleteArtifact` revoking in a transaction. Files: `src/database/schemas/share-link.ts`, the generated migration SQL, `meta/` snapshot and `_journal.json` (`mise exec -- pnpm db:generate`), `src/database/repository.ts`, `src/database/repository.unit.test.ts`. Acceptance: `mise exec -- pnpm exec vitest run src/database`; tests prove that a second live link is refused, that soft delete then restore leaves the link revoked, that purge removes the row, and that a revoked, unknown, or deleted token resolves to `undefined`.
2. Server fns. Goal: `getSharedArtifactFn` (public) and `createShareLinkFn`, `getShareLinkFn`, `revokeShareLinkFn` (session-guarded). Files: `src/lib/share-links.ts`, `src/lib/share-links.int.test.ts`, `src/lib/server-fn-protection.unit.test.ts`. Acceptance: `mise exec -- pnpm exec vitest run src/lib/share-links.int.test.ts src/lib/server-fn-protection.unit.test.ts`; tests prove the public fn returns exactly the keys `title`, `type`, `body` and returns `null` for HTML in v1, and that each owner fn throws without a session.
3. Public page. Goal: `/s/:token` renders spec or markdown without app chrome and without a store, with a 404 identical for every miss and the three headers set by route server middleware. Files: `src/routes/s.$token.tsx`, `src/components/artifacts/shared-artifact-view.tsx`, `src/components/artifacts/shared-artifact-view.unit.test.tsx`, `src/routes/route-protection.unit.test.ts`, `src/routeTree.gen.ts` (generated). Acceptance: `mise exec -- pnpm exec vitest run src/routes src/components/artifacts`, then an E2E check on a throwaway server (port 3100, scratchpad DB) that confirms the headers with `curl -I` on a live and a revoked token, and confirms that toggling a checklist writes no `artifact_states` row.
4. Owner UI. Goal: a "Share link" menu item and dialog that creates, copies, and revokes the link and shows the pinned version against the latest. Files: `src/components/artifacts/share-link-dialog.tsx`, `src/components/artifacts/share-link-dialog.unit.test.tsx`, `src/components/artifacts/artifact-detail.tsx`. Acceptance: `mise exec -- pnpm exec vitest run src/components/artifacts`; the dialog uses house `Form` + `Field` with `useFormAction` and 32px controls, and it is hidden for HTML artifacts.
5. Docs and invariants. Goal: the `CLAUDE.md` public-route line (and the HTML-surface line only if row 2 is accepted) and `README.md` describe share links, and the route-protection comment matches. Files: `CLAUDE.md`, `README.md`, `src/routes/route-protection.unit.test.ts` (comment only). Acceptance: `grep -n '/s/:token' CLAUDE.md README.md` matches both files; `mise exec -- pnpm gate`.

If Henry accepts row 2, phase 3 gains `src/routes/s.$token_.raw.ts` and its unit test, and the page loader redirects HTML tokens to it.
